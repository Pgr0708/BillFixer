# ADR-003: Deterministic Analysis Before LLM

**Date:** 2026-09-27
**Status:** Accepted

## Context
A naive implementation might send the full bill to an LLM and ask "what's wrong with this bill?"
This creates hallucination risk (LLM inventing findings), unpredictable costs, and no evidence basis.

## Decision
All findings are generated by deterministic business logic (pure math, comparison, lookup).
The LLM is ONLY used to:
1. Write human-readable explanations of already-determined findings
2. Draft letters and scripts based on already-assembled evidence bundles

The LLM cannot create new findings. It can only explain findings that the deterministic engine produced.

## Consequences
- Findings are grounded in evidence (no hallucination risk for finding detection)
- Higher upfront engineering cost (deterministic rules must be coded explicitly)
- More predictable and auditable output
- Legal defensibility: "The bill's math was verified programmatically"
